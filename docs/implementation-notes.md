# Implementation Notes

- The app stores authenticator entries as JSON at `authenticator-codes.json` in the app documents directory.
- TOTP generation supports otpauth TOTP URLs and manual Base32 secrets with SHA1, SHA256, or SHA512.
- Manual entry always shows issuer, account, and secret fields. It attempts to prefill the secret from a raw Base32 clipboard value, or all fields from an `otpauth://` clipboard URL.
- Manual entry defaults an empty issuer to the current date in `yyyy-MM-dd` format when saving.
- Rows copy the current code to the system pasteboard, show a short copied toast, and update `lastCopiedAt`.
- Rows expose a swipe Edit action that opens a sheet for changing issuer, account, and secret.
- Rows display the previous TOTP code next to the current code in a smaller muted style.
- Build 4 (CFBundleVersion 4) switched the secondary row code from the next code to the previous code (computed one period back, `now - period`). The AutoFill extension's `AutofillInfo.plist` now carries explicit `CFBundleVersion`/`CFBundleShortVersionString` matching the app — previously Xcode defaulted the appex version to `1`, which blocked simulator launch and risked TestFlight rejection; `~/.local/bin/bump-build` keeps extension plists in sync.
- A circular refresh indicator in the leading navigation toolbar shows progress for the next visible code refresh and hides the iOS 26 shared toolbar background.
- Rows show compact copied time in the top-right using social-style values like `now`, `1m`, `1h`, or `1d`; never-copied rows show `never`.
- Code ordering is descending by `activityDate` (`lastCopiedAt` if set, else `createdAt`), so freshly scanned never-used codes sort to the very top and copying still promotes a code to the top.
- Entries with an `activityDate` older than a week and archived entries are grouped in an `Older` section that is collapsed by default and expanded while searching. A never-used code moves to `Older` once its `createdAt` is more than a week old.
- Rows expose a swipe Archive/Unarchive action (context-sensitive label). Archiving forces an entry into the `Older` section until it is copied; copying clears the archived flag. Google migration imports and other imports start with `isArchived = true`, so they land in `Older` until used, while manually added codes and individual QR scans use `isArchived = false` and appear at the top of the recent section.
- The `Older` toggle is rendered as a plain list row, not a SwiftUI section header, to avoid default header spacing.
- Copy-driven row reordering uses a short non-bouncy ease-in-out animation to avoid row overshoot when a copied code moves to the top.
- Search filters entries by issuer, account, or display name while preserving existing ordering.
- Search uses the native `.searchable` field placed in the bottom toolbar (`DefaultToolbarItem(kind: .search, placement: .bottomBar)` on iOS 26+, matching Messages); it is hidden while there are no codes. The copied toast sits above the bottom bar so it does not cover the search field.
- QR import uses AVFoundation metadata scanning and requires `NSCameraUsageDescription` in `Info.plist`.
- The QR scanner sheet includes a Cancel button over the camera preview to dismiss without importing.
- Google Authenticator migration imports decode `otpauth-migration://offline?data=...` protobuf payloads and import TOTP entries from them.
- `Info.plist` registers the `otpauth` and `otpauth-migration` URL schemes; incoming links are imported through `ContentView.onOpenURL`.
- AutoFill one-time-code support uses a credential provider extension, App Group shared JSON storage, and `ASCredentialIdentityStore` identities on iOS 18+.
- The main app and AutoFill extension both carry `com.apple.developer.authentication-services.autofill-credential-provider`; App Store/TestFlight validation requires the containing app bundle to include it when shipping the credential provider extension.
- Shared storage uses the App Group `group.tech.stupid.StupidAuthenticator`.
- `web/` contains a Bun/Vite TypeScript tester for generating TOTP enrollment QR codes and expected current codes.
- The App Store listing (name "stupid totp", subtitle "Fast frequent TOTPs", tagline "TOTP that stays out of your way") and 6.9" screenshots (APP_IPHONE_67, 1290×2796) were submitted via the `appstore-release` skill. Screenshots capture the main code list and the expanded Older section.
- The skill is generic and stores no personal defaults: global credentials live in `~/.config/opencode/env/appstore-release.env`; project values (`APP_BUNDLE_ID`, `XCODE_WORKSPACE`, `XCODE_SCHEME`, `BETA_APP_DESCRIPTION`) live in the project's gitignored `.env.local`.

- Home Screen quick actions are received by `QuickActionSceneDelegate`, which `AppDelegate.application(_:configurationForConnecting:options:)` names as the scene delegate class (SwiftUI still creates the `WindowGroup` window). Cold launches read the action from the scene connection options; warm launches get `windowScene(_:performActionFor:completionHandler:)`. Actions that arrive before the store connects are deferred until `connect(store:)`. The earlier approach (adding the handler to SwiftUI's `AppSceneDelegate` at runtime and reading `launchOptions`) stopped working on iOS 27: `AppSceneDelegate` already implements the selector without forwarding it, and scene-based launches never put the action in `launchOptions`. Successful quick-action copies trigger the same copied toast as row taps after the app transition completes.

- Keychain sync (build 11): each `AuthenticatorEntry` now persists as its own synchronizable generic-password Keychain item in the `group.tech.stupid.StupidAuthenticator` access group (`service` `tech.stupid.StupidAuthenticator.authenticator-entry.v1`, payload `AuthenticatorKeychainRecord` version 1, `kSecAttrAccessibleWhenUnlocked`). The AutoFill extension reads the same items directly from Keychain instead of the shared JSON file.
- `AuthenticatorStore` now depends on the small `AuthenticatorRepository` protocol and uses `AuthenticatorKeychain` in production. Mutations persist before publishing (`add`, `update`, `delete` throw; `markCopied`/`setArchived` surface a non-secret warning without failing the copy); a failed write after a partial multi-item mutation reloads the repository and publishes what actually persisted.
- A refresh that fails with `errSecInteractionNotAllowed` (device locked) keeps the current snapshot without a warning. On a Mac the app stays active while the screen is locked, so the 30-second poll used to hit this and show "Couldn't save changes" when the user came back. The app also refreshes on `UIApplication.protectedDataDidBecomeAvailableNotification`. Other refresh failures still surface a warning.
- Legacy JSON (`authenticator-codes.json`) is read only for upgrade migration. On launch the store queries Keychain first; if the query fails it retains readable legacy entries in memory, shows a persistence warning, and marks/delete nothing. Otherwise it imports UUIDs missing from Keychain (`insertIfAbsent`, idempotent), verifies every legacy UUID, writes the atomic marker `keychain-migration-v1.complete` in the App Group container, then removes both legacy JSON candidates. The existing Keychain value wins when a UUID exists in both stores.
- The app reloads the Keychain snapshot whenever the scene becomes active and polls every 30 seconds while active, publishing only when the loaded array differs (avoids pointless AutoFill identity/quick-action rebuilds). A transient query failure retains the previous snapshot.
- Added `Tests/StupidAuthenticatorTests/AuthenticatorStoreTests.swift` (in-memory fake repository + temp dirs; covers load ordering, persistence-before-publish, partial-failure reloads, duplicate displacement, refresh semantics, and migration idempotency/guards) and `Tests/StupidAuthenticatorTests/AuthenticatorKeychainTests.swift` (record envelope round-trip, deterministic UUID order, malformed/unknown-version/uuid-mismatch rejection with warnings).
- No new entitlement was added: on iOS, App Group membership grants the matching Keychain access group automatically, and the `keychain-access-groups` entitlement/`Keychain Sharing` capability is not needed (Apple explicitly allows app group names as keychain access group names without that entitlement). This was validated against Apple's docs; the physical-device release gate is the real proof.
- Simulator caveat: iOS simulators cannot exercise the App-Group Keychain with `stupid-app`'s ad-hoc simulator signing — the effective access-group list does not include the app group without an `application-identifier` entitlement, and embedding `application-identifier` into an ad-hoc sim build makes launchd refuse to spawn it (`Security policy issue`, POSIX 163; `errSecMissingEntitlement` -34018 otherwise). On the simulator the app therefore exercises the "Keychain query failed → retain legacy entries + warning + preserve files" path (verified in the running app), while all repository semantics are covered by the unit-test fake. Real Keychain behavior requires the signed two-device physical gate. Also, `stupid-app run --simulator` produces a plugin-bearing bundle whose nested code seal fails launch on iOS 26.3 slim; `codesign --force --deep -s -` (or `--preserve-metadata=entitlements`) on a copy restores launch.

- Physical-device validations for the Keychain sync gate (build 11, 1.2.0), run by the developer on real devices with the same Apple Account / iCloud Passwords & Keychain:
  - A device running the previous JSON build was upgraded to build 11; a fresh build 11 install on a Mac then displayed the codes without any opt-in — i.e. the device migration imported existing codes into Keychain, iCloud Keychain synchronized them, and the fresh install read them straight from Keychain.
  - Adding an entry on one device propagated to the other (active-scene reload + 30s poll picked up the remote item).
  - Deleting an entry on one device removed it from the other device.
  - This confirms on signed devices that App-Group membership alone grants the matching Keychain access group (no `keychain-access-groups`/Keychain Sharing capability was added), and that synchronizable generic-password items in the `group.tech.stupid.StupidAuthenticator` access group propagate as designed.
